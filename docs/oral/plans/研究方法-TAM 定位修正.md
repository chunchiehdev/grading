## 一、為什麼老師說「這不是 TAM」？

### TAM 到底是什麼？

TAM（Technology Acceptance Model, Davis, 1989）**不是「三個 Likert 量表向度」**，
而是一個**因果關係模型**，主張：

```
外部變項 → PEOU（易用性）───┐
                           ├→ PU（有用性）─┐
PEOU ─────────────────────┘               ├→ ATU（態度）─┐
                                          │             ├→ BI（行為意圖）→ AU（實際使用）
PU ────────────────────────────────────────┘            │
                                                        │
ATU ────────────────────────────────────────────────────┘
```

要「做 TAM 研究」**必須**做到以下其中之一：

1. **路徑驗證**：用結構方程模型（SEM）或多元迴歸驗證 PEOU → PU → ATU → BI 等路徑
2. **假設檢定**：提出 TAM 的因果假設並用統計方法檢驗（例如 H1: PEOU 顯著預測 PU）
3. **行為意圖測量**：至少要量到 BI（Behavioral Intention），TAM 的最終預測變項
4. **模型適配度評估**：報告 χ²/df、CFI、TLI、RMSEA 等模型適配指標

### 你實際做了什麼？

| TAM 必備元素 | 你的研究 |
|---|---|
| PU、PEOU 量表 | ✅ 有（PU 6 題、PEOU 5 題） |
| ATU 量表 | ✅ 有（3 題） |
| BI（行為意圖）量表 | ❌ 沒有 |
| AU（實際使用）測量 | ❌ 沒有 |
| 路徑分析（PU → ATU 等） | ❌ 沒有 |
| 結構方程模型（SEM） | ❌ 沒有 |
| TAM 假設檢定 | ❌ 沒有 |
| 模型適配度報告 | ❌ 沒有 |
| 各構面**描述統計** | ✅ 只有這個 |
| Cronbach's α 信度 | ✅ 有 |

**結論：你只是借用了 TAM 的三個向度名稱當作問卷設計參考，
然後對每個向度做平均數與標準差。這在方法論上叫做：**

> **「TAM 啟發的使用者評估問卷」（TAM-informed user evaluation questionnaire）**
> 或
> **「以 TAM 構念為參考之描述性問卷調查」**

**而不是「TAM 研究」。**

## 二、這個誤用為什麼很常見？

很多碩博論文都犯這個錯。因為：

1. 用 TAM 的名字看起來很「有理論架構」
2. PU/PEOU 三個向度當問卷向度設計很方便
3. 不知道 TAM 本質是「因果模型」而不是「量表分類」

但嚴格的方法論審查者（你的老師就是）會指出：
**「沒驗證 TAM 路徑 = 沒做 TAM」**。

## 五、口試現場的兩種說法

### 說法 A：被問「你做的是不是 TAM？」

> 「**嚴格來說不是。** 我**參考了** TAM 的三個構念（PU、PEOU、ATU）來設計使用者評估問卷，但**沒有測量行為意圖（BI），也沒有用 SEM 驗證 TAM 的路徑關係**。所以我這個量表的定位是『**參考 TAM 構念的使用者評估問卷**』，而不是 TAM 模型驗證研究。論文裡我會把『以 TAM 為研究框架』改為『參考 TAM 構念設計問卷』，避免過度宣稱。」

### 說法 B：被問「為什麼不做完整的 TAM？」

> 「因為本研究**定位為系統開發後的初步評估**，重點在於**描繪學生對系統的主觀評價**，而不是**驗證 TAM 理論模型**。完整的 TAM 路徑驗證需要更大樣本（一般建議 200+）與 SEM 分析，這超出本研究的範圍。我用三個構念做描述統計，是為了給未來研究與系統迭代提供基礎資料，**後續研究可以在此基礎上進行完整的 TAM 模型驗證**。」

這兩個說法都**承認限制 + 解釋為何如此設計 + 指出未來方向**，是口試的標準回應結構。
